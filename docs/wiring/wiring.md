# Wiring - Hollygrove Community Fridge door counter

Diagram: `\\TRUENAS\Pyle-TNAS_Individual\Projects\Microcontrollers\esp32-fridge-counter\docs\wiring\wiring-diagram.svg` (open it in a web browser; it prints on one letter-size page in landscape). It is generated by `tools\gen_wiring_svg.py`; if a pin ever changes, change `include\config.h` and that script together, then run `python tools\gen_wiring_svg.py`.

The pin numbers in the firmware are in `include\config.h`. Every number below is an ESP32-S3 **GPIO number**, which is what the board's silkscreen prints next to each pin (for example the pin marked `4` is GPIO4).

## Which board do I have?

The owner has two kinds of ESP32-S3 board. The same firmware and the same GPIO numbers work on both; only the physical pin positions and the breakout board differ.

| Check | AYWHP ESP32-S3-DevKitC-1 (N16R8) | Freenove ESP32-S3 WROOM / Board Lite |
| --- | --- | --- |
| Pins per side | 22 | 20 |
| Left column starts with | `3V3`, `3V3`, `RST`, `4` | `3V3`, `RST` (or `EN`), `4` |
| Word "FREENOVE" printed on the board | no | yes |
| microSD card slot | no | yes on the WROOM board (check the underside) |
| Serial `pins` command, GPIO38 to 40 | "free (floating)" | "pulled HIGH" (the SD slot's pull-up resistors), if the board has the slot |
| Small extra LED on GPIO2 | no | yes ("LED ON" in Freenove's pinout) |
| RGB status LED | GPIO48 | GPIO48 |

The board on the bench on 2026-11-14 (MAC 30:ed:a0:b8:9e:68, 16 MB flash, 8 MB PSRAM) is the **DevKitC-1 style** board: its factory demo program drove an RGB LED on GPIO48 and the `pins` command showed GPIO38 to 40 floating. Nobody has looked at it by eye yet; counting the pins per side settles it.

What changes for the Freenove board: nothing in the firmware. The wires go to the same GPIO numbers, in the same order down each side (the DevKitC simply has one extra `3V3` at the top left and extra `GND` pins). Keep the Freenove's microSD slot **empty**: the card would share GPIO38, 39 and 40 with HX711 scales #2 to #4.

## Active and dormant parts

- Active now: reed switch (GPIO4), status LED (GPIO48), WiFi.
- Dormant until plugged in: BMP280/BME280, DS18B20, DHT11/DHT22, HX711 scales. To use one, wire it and press the board's RST button (or type `probe` in the serial monitor); it is then found automatically. The firmware also looks again once an hour.
- Reserved: RS485 pins 16, 17, 18 for a later link to the solar inverter. Do not wire anything else to them.

## Parts

On hand: reed switch with magnet, BMP280 modules, probably a DHT11 (in a starter kit), jumper wires, the breakout boards below.

To buy:

- DS18B20 waterproof probe (3-wire, with stainless tip) and a 4.7 k resistor (often included with the probe).
- HX711 amplifier boards with load cells (one per shelf, up to four). Experimental.
- BME280 (optional; adds humidity, same wiring as the BMP280).
- RS485 module: buy a **3.3 V** type (MAX3485 or SP3485). The common MAX485 boards are 5 V parts.
- For the field: a 5 V buck converter (from the battery or solar system) with at least 1 A.

## Which screw-terminal breakout fits

- **Freenove Breakout Board for ESP32 / ESP32-S3 (WROVER, WROOM)**, the board with GPIO numbers printed beside each terminal (Freenove FNK0091, board CB9101): its sockets are 20 per side and its labels follow the Freenove ESP32-S3 WROOM pinout. It fits the **Freenove** boards. It does **not** fit the 22-pin DevKitC-1 style board: the board would overhang the sockets and every printed label would be wrong. Use it with the Freenove board.
- **Freenove Universal Breakout Board** (Freenove FNK0101): has long socket rows with no fixed pin names; Freenove says it takes any board whose two pin rows are between 600 mil and 1000 mil (15.2 to 25.4 mm) apart, in any position. This is the one for the **DevKitC-1 style** board. Its terminals carry no GPIO names, so read the GPIO number off the ESP32 board itself and label the terminals with tape. Measure the DevKitC's row spacing first: if it is over 25.4 mm, it does not fit.

Both breakouts have their own 5 V and 3.3 V regulators fed from a barrel jack. If you power the breakout from the jack, do not also plug a USB cable into a power-only charger; a laptop USB connection for programming is fine.

## Cautions in plain language

- **3.3 V logic.** Every GPIO pin works at 3.3 V. Putting 5 V on any GPIO pin can destroy the chip. Power every sensor from `3V3`, not from `5V`, and they will only ever send 3.3 V back.
- **Unplug before rewiring.** Unplug USB (and the 5 V supply) before moving wires.
- **Pins to leave alone on this board, and why:**
  - GPIO0, 3, 45, 46: "strapping" pins. The chip reads them at the instant it starts to decide how to boot. A sensor holding one of them high or low can stop the board from starting or put it in programming mode.
  - GPIO35, 36, 37: connected inside the module to the 8 MB PSRAM memory chip on the N16R8 and N8R8 modules. Touching them can crash the board.
  - GPIO19, 20: the native USB port's data lines.
  - GPIO43 (TX), 44 (RX): the serial port you see in the monitor.
  - GPIO48: the on-board RGB status LED.
  - GPIO26 to 32: the flash memory chip (not on the headers at all).
- **ADC2 and WiFi.** GPIO11 to 20 belong to the chip's second analogue converter, which cannot take analogue readings while WiFi is on. This firmware reads no analogue signals, so it does not matter today. Any future analogue sensor (a battery voltage divider, for example) should go on GPIO1, 2, 7 or 10 (first converter).
- **GPIO38 to 42** double as the chip's debugging (JTAG) pins and, on the Freenove board, the SD slot. Ordinary digital use is fine; this firmware uses them only for the experimental HX711 scales.
- **Genuine Espressif DevKitC-1 v1.1 boards** put the RGB LED on GPIO38 instead of 48. The owner's boards use 48. On a genuine v1.1 board set `STATUS_LED_PIN 38` in `include\config.h` and do not connect HX711 #4.
- **Long reed-switch wires** (more than a couple of metres) pick up noise. The 50 ms debounce handles ordinary noise; if false counts appear, use twisted pair or shielded cable and add a 100 nF capacitor from GPIO4 to GND at the board.

## DS18B20 pull-up

The DS18B20 data line needs a 4.7 k resistor between DATA (yellow wire) and 3V3 (red wire). Fit it at the board end, at the screw terminals. Without it the sensor is not found (it simply stays dormant). Use the 3-wire connection (red to 3V3, black to GND, yellow to GPIO5); the firmware does not support "parasite power" with only two wires.

## RS485 header (reserved)

Keep GPIO16, 17 and 18 free and, if convenient, fit a 5-pin header or label five terminals for a later RS485 module: 3V3, GND, DE+RE (GPIO16, the module's DE and RE pins joined), DI (GPIO17), RO (GPIO18). The module's A and B terminals go to the inverter's RS485 port. No firmware drives these pins yet.

## 5 V power in

- Bench: plug a USB-C cable into the port marked **UART** or **COM** (the CH343 serial chip; this is also the programming port). Nothing else.
- Field: feed regulated 5 V into the `5V` pin and GND. A 5 V buck converter from the battery bank is the plan (see `docs\power-and-enclosure.md`).
- Never feed the `5V` pin and USB at the same time from two different supplies. If the board must be programmed in the field, disconnect the 5 V supply first, or use the breakout's barrel jack with USB from a laptop only.
- Never feed anything into the `3V3` pin; it is an output from the board's regulator.

## Same signals on a Walter board

Walter (DPTechnics / QuickSpot) is an ESP32-S3 with an LTE-M modem on the same board. The firmware's `walter` build uses the same GPIO numbers as above. The modem itself uses GPIO14, 21, 45, 47 and 48 (from the WalterModem library source: modem RX 14, TX 48, RTS 21, CTS 47, reset 45), so those must not be wired to anything.

| Signal | GPIO on Walter | Notes |
| --- | --- | --- |
| Reed switch | 4 | Same as above. |
| DS18B20 data | 5 | 4.7 k pull-up to Walter's 3.3 V output. |
| DHT data | 6 | |
| I2C SDA / SCL | 8 / 9 | |
| RS485 DE / TX / RX (reserved) | 16 / 17 / 18 | |
| HX711 SCK | 42 | |
| HX711 DT #1 to #4 | 41, 40, 39, 38 | |
| Status LED | none | Walter has no RGB LED on GPIO48 (that pin is the modem's TX line); the firmware switches the LED off in the `walter` build. |
| Modem (do not use) | 14, 21, 45, 47, 48 | Used by the LTE modem. |
| Strapping (avoid) | 0, 3, 46 | GPIO45 is already the modem reset. |

Before soldering to a Walter, check each GPIO number against Walter's own pinout card from DPTechnics: Walter was not on hand when this was written, so its header layout and its power pins (input voltage range, switched 3.3 V output) have not been checked against the board.
